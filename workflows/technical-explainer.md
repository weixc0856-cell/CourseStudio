# Workflow — Technical / Paper Explainer

适用于论文、技术文档、工程方法、算法、系统和数值实验的解读。目标是**讲清机制、证据和边界**，不是把摘要扩写成长文。

> 制作成课程或视频时，按 [episode-pipeline.md](episode-pipeline.md) 的 `technical` 模式执行；本文件保留论文机制与证据检查规则。

## 读取顺序（低 Token）

1. 本文件。
2. [guides/editorial-voice.md](../guides/editorial-voice.md)。
3. [guides/delivery-quality.md](../guides/delivery-quality.md)。
4. Skill 的 `references/source-and-claims.md`。
5. 按领域读 `references/domain-checks.md`：AI/软件、科学论文、CFD/数值模拟、量化研究等。
6. 默认动画路径读 `tools/skills/motion-isolation/SKILL.md`；只有 Manim 兜底时读 `references/manim-workflow.md`。

## 阶段

### 0. 问题与范围

- 这篇论文/文档解决什么问题？
- 受众需要什么先备知识？
- 本单元解释机制、结果、方法，还是三者都讲？
- 明确排除项（训练细节、完整推导、工程部署等）。

### 1. 来源与方法

- 原始论文/官方文档/代码/数据优先。
- 记录版本、发布日期、章节/公式/图表/代码路径。
- 区分作者主张、实验观察、定义、推导、工程建议。
- 检查基线、指标、数据、假设、适用范围。
- 不把摘要当全文；不把博客复述当原始证据。

### 2. 公式、代码与数值

- 明确符号、张量形状、维度、方向、单位、归一化轴。
- 公式与代码、图示、旁白一致。
- 关键中间值可复算；用独立实现或手算交叉核对。
- 代码示例实际可运行或明确标记为伪代码。
- 区分教学简化与真实实现；简化要标注。
- 舍入、精度、随机种子、版本记录清楚。

### 3. 解释机制

- 先给直觉模型，再给形式定义，再给 worked example。
- 一次引入一个主要概念变化。
- 动画只在运动/状态变化能解释机制时使用；不要用动画装饰。
- 每个动画步骤说明：初态、变化、为什么变、观众该看哪里、末态。

### 4. 证据与边界

- 作者的结论是否超出实验范围？
- 基线是否公平？指标定义是否一致？
- 有没有反例、失败模式、消融、后续工作或独立复现？
- 计算复杂度不等于 wall-clock 性能；模拟收敛不等于物理验证。
- 明确哪些是事实、推导、推断、假设、工程经验。

### 5. 视觉

- 公式、矩阵、流程图、数据流优先 HTML/SVG；连续变换/几何/数值过程用 Motion Canvas（默认）；Manim 仅在 `engine=manim` 时兜底。
- 图表标单位、轴、来源、定义。
- 颜色映射一致；Q/K/V 等角色在页面和动画中使用同一套颜色。
- 静态末态可读；不要只把关键信息放在运动中。

### 6. 观众版与内部 QA

- 观众版保留理解所需的公式、数字、形状、限定和来源。
- 工具失败、未跑测试、claim ID、内部路径、渲染元数据放 `qa/` 和 `research/`。
- 最后一页放继续阅读和观众相关范围，不放审计清单。

### 7. QA

- [ ] 公式、代码、图示、旁白的符号和数值一致。
- [ ] 张量形状/维度/方向明确。
- [ ] 关键中间值有独立核验。
- [ ] 简化模型与真实模型区分。
- [ ] 基线、指标、数据、假设、适用范围已检查。
- [ ] 失败模式/限制/反证已考虑。
- [ ] 代码示例可运行或标记为伪代码。
- [ ] 动画抽帧检查；页面浏览器检查。
- [ ] 观众版泄漏扫描。
- [ ] 未执行的检查标记 `NOT_RUN` / `PARTIAL`。

## 硬性规则

- 不编造实验、基准、引用、代码输出或渲染结果。
- 不把作者主张写成独立验证的事实。
- 不把复杂度分析写成性能承诺。
- 不把仿真/模型结果写成实验证明。
- 程序检查通过不等于科学结论正确。
- 不自动提交、推送或发布。
