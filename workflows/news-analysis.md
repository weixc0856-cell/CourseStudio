# Workflow — News Analysis

适用于新闻、政策、公司事件、市场变化、产品发布和行业动态的解读。目标是**把已确认的事实、来源的引述、分析、预测和意见分开**，不是把标题扩写成故事。

> 制作成视频或播客时，按 [episode-pipeline.md](episode-pipeline.md) 的 `news` / `podcast` 模式执行；本文件保留新闻事实与证据判断规则。

## 阶段

### 0. 研究截止与来源盘点

- 记录研究截止时间（含时区）。
- 列出所有来源：类型、发布日期、事件日期、数据期间、URL/文件、访问日期。
- 区分原始文件（公告、财报、监管文件、论文、数据、法院文件）与二手报道。
- 记录无法访问的来源；不要用搜索片段替代原文。
- 记录哪些事实可能继续更新。

### 1. 主张分类

每个重要主张至少标注一类：

| 类型 | 含义 | 写法 |
| --- | --- | --- |
| 已确认事实 | 可直接观察/记录，有明确范围与日期 | “X 公司于 2026-… 发布…” |
| 来源引述 | 某人/机构如此主张，不等于事实 | “公司称…”“监管文件写道…” |
| 分析 | 基于证据的解释 | “一个可能的机制是…” |
| 预测 | 有条件的未来判断 | “如果…，则…；关键假设是…” |
| 假设 | 分析所用的前提 | “假设…；若不成立，结论会变。” |
| 意见/价值判断 | 规范性或评价性 | “我认为…” |

不要把引述写成事实，不要把分析写成已确认，不要把预测写成必然。

### 2. 独立性与反证

- 多篇文章引用同一篇通稿/同一个信源，只算一条来源链。
- 找第二条独立证据路径：原始数据、监管文件、独立分析、 replication、直接观察。
- 记录利益相关关系：公司、政府、行业组织、资助方、分析师持仓等。
- 主动找最强反证和替代解释；不要只收集支持叙事的材料。
- 来源冲突时保留冲突，解释可能的定义、日期、口径或方法差异。

### 3. 叙事结构

按需要选择以下节拍，不必全部套用：

1. 发生了什么/被主张了什么？
2. 哪些已确认，由谁确认？
3. 相对之前的状态，改变了什么？
4. 可能的机制是什么？
5. 谁受影响，通过什么渠道？
6. 最强的替代解释是什么？
7. 还缺什么证据？
8. 哪些新证据会改变当前判断？

短解读不必强行八段。删掉不增加理解的节拍。

### 4. 视觉与数据

- 图表标单位、时间、口径、来源、定义。
- 区分名义/实际、水平/增长率、存量/流量、季调/未季调。
- 不截断坐标轴误导；说明对数、指数化、归一化、修订。
- 预测展示区间/情景，不展示假精确。
- 时间线、地图、流程图只在降低理解成本时使用。

### 5. 观众版与内部 QA

观众版：

- 清楚区分已确认、引述、分析、预测、意见。
- 保留会影响结论的未知、冲突和更新条件。
- 不写工具失败、未跑测试、内部路径、claim ID。

内部：

- 来源登记、主张账本、访问失败、独立性判断、未解决问题放 `research/` 和 `qa/`。

### 6. QA

- [ ] 研究截止时间、事件日期、数据期间分别记录。
- [ ] 标题没有被当作已证实结论。
- [ ] 每个关键数字有来源、单位、口径。
- [ ] 引述准确，未被改写成事实。
- [ ] 独立来源链已识别；没有把转载当 corroboration。
- [ ] 最强反证/替代解释已考虑。
- [ ] 预测的假设和更新条件明确。
- [ ] 没有为了叙事完整而填补证据空白。
- [ ] 观众版没有内部状态或审计话术。
- [ ] 图表没有误导性坐标/截断/精度。

## 硬性规则

- 新闻标题是线索，不是证据。
- 不编造引述、数字、日期、来源或“接近事件的人”。
- 不把相关性写成因果；不把市场叙事当成因果证明。
- 不隐藏来源冲突和不确定性。
- 没有人工事实审查时，不宣称结论已经独立验证。
- 不自动发布、不自动提交 Git。
