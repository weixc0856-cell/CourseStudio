枚举：

| 字段 | 枚举 |
| --- | --- |
| `claim_type` | FACT / CLAIM / INFERENCE / ASSUMPTION / REPRODUCED_RESULT |
| `evidence_status` | DIRECTLY_SUPPORTED / PARTIAL / UNSUPPORTED / NOT_CHECKED / NOT_APPLICABLE |
| `reasoning_status` | VALID / FLAWED / INCOMPLETE / NOT_APPLICABLE / NOT_CHECKED |
| `execution_status` | NOT_RUN / THEORETICAL_ONLY / EXECUTED / REPRODUCED / BLOCKED / NOT_APPLICABLE |
| `validation_status` | PASSED / FAILED / PARTIAL / NOT_RUN / BLOCKED |
| `conflict_status` | NONE / POTENTIAL_CONFLICT / CONFIRMED_CONFLICT / NOT_CHECKED |

条件规则（Schema + 语义）：

- FACT/CLAIM/INFERENCE/REPRODUCED_RESULT 必须有 `source_ids` 和 `source_locators`（Schema `if/then`）。
- `REPRODUCED_RESULT` 必须有 `execution_status=REPRODUCED` 且 `validation_status=PASSED`（Schema）。
- `source_ids` 集合必须等于 `source_locators[].source_id` 集合（语义；测试覆盖）。
- `used_in_artifact` 必须能解析到 deck/segment/cue/recording（语义；测试覆盖）。
- `DIRECTLY_SUPPORTED` 不允许 `validation_status=NOT_RUN`（语义；测试覆盖）。
- `review_notes.decision` 只能是 PENDING/ACCEPTED/REJECTED；由人填写（文档规则；未自动检查）。

**结论**：字段数量/命名/枚举/引用一致性已核对；“Core 14”与“15 字段”的混用已在 `schemas/README.md` 冻结为 15 字段。真实课程仍是 8 列，迁移未执行。

## 2. `mini_schema.py` 与 Draft 2020-12 的差距

`mini_schema.py` 支持的 27 个关键字：

```text
$ref, type, required, properties, additionalProperties, enum, const,
pattern, minLength, maxLength, minimum, maximum, minItems, maxItems,
uniqueItems, items, allOf, anyOf, oneOf, if, then, else
```

（以及类型名 object/array/string/integer/number/boolean/null。）

**未支持**的常见 Draft 2020-12 关键字/能力：

| 类别 | 未支持项 | 影响 |
| --- | --- | --- |
| 字符串格式 | `format`（date-time、email、uri 等） | 时间戳/URL 只检查字符串，不检查格式 |
| 数值 | `multipleOf`、`exclusiveMinimum`、`exclusiveMaximum` | 更细的数值约束无法表达 |
| 对象 | `patternProperties`、`propertyNames`、`minProperties`、`maxProperties`、`dependentRequired`、`dependentSchemas` | 动态键/依赖关系无法表达 |
| 数组 | `prefixItems`、`contains`、`minContains`、`maxContains` | 元组/包含约束无法表达 |
| 组合 | `not`、`unevaluatedProperties`、`unevaluatedItems` | 复杂排除/未评估属性无法表达 |
| 引用 | 外部 `$ref`、`$id` 解析、`$anchor`、`$dynamicRef`、`$recursiveRef` | 只支持本地 `#/$defs/...` |
| 元数据 | 布尔 schema、注解、`contentEncoding`、`contentMediaType` | 不支持 |
| 元验证 | 不对 JSON Schema 自身做 meta-schema 校验 | 不能证明 schema 文件符合 Draft 2020-12 |

另外：

- `format` 被明确忽略；`created_at`/`reviewed_at` 等只是非空字符串。
- `uniqueItems` 使用 Python 相等性；对对象数组可用，但不是完整 JSON Schema 等价语义。
- 没有 `$id` 解析，因此不能安全引用外部 schema。
- 没有 `additionalProperties` 之外的未评估属性处理；本契约使用 `additionalProperties:false`，所以当前 fixtures 足够，但未来扩展可能踩坑。

**结论**：当前 24 项测试只能证明“本契约使用的关键字子集”通过，**不能**声称“完整 Draft 2020-12 通过”。R1 报告已把完整验证标为 `NOT_RUN`。

## 3. 完整 JSON Schema 验证器可用性

| 检查 | 结果 |
| --- | --- |
| `python -c "import jsonschema"` | `ModuleNotFoundError`（未安装） |
| `tools/slidev-runtime/node_modules/ajv` | 不存在 |
| 系统/项目内独立 contract runtime | 尚未创建 |

**可选方案**：

1. **项目内 Python contract runtime（推荐）**
   新建 `tools/contract-runtime/`，`uv add jsonschema==<exact>`，提交 `pyproject.toml`、`uv.lock`、`.python-version`；CI 用 `uv sync --frozen`。不安装全局包，不影响生产 checker。版本必须在解析后固定，不能凭记忆写版本号。
2. **Node/Ajv**
   需要新增 pnpm 依赖；当前 Slidev runtime 没有 Ajv。会引入第二语言栈，不推荐。
3. **vendor 一个最小验证器**
   维护成本高，且仍不是完整 Draft 2020-12；不推荐作为“完整验证”的替代。

**依赖锁定要求**：

- 精确版本 + `uv.lock` + `.python-version`；
- CI 使用 `--frozen`；
- 记录许可证；
- 本地/CI 不共享全局 site-packages；
- R2.1 需要负责人批准新增依赖。

## 4. 严格 QA 假绿：原因与修复位置

本次只读复核 `tools/check-episode.py`：

| 行 | 代码/行为 | 影响 |
| --- | --- | --- |
| 403 | `probe_error = "no recording (NOT_VERIFIED)"`，无录像时不加入 warnings | 无录像不影响状态 |
| 817 | `if not handoff: warnings.append("missing handoff.md")` | 缺 handoff 只是 warning |
| 828 | `build_info["skipped"] = "Reveal deck: build check deferred to Phase 4"` | Reveal 无构建/浏览器证据 |
| 830 | `status = "FAIL" if issues else ("PASS_VERIFIED" if not warnings else "PARTIAL")` | 结构检查通过就输出 `PASS_VERIFIED` |
| 945 | `return 1 if issues else 0` | warnings/PARTIAL 仍 exit 0 |
| 557 | recording manifest cue 缺失是 warning | 录制包不完整仍可过 |

**实际复现**（R2.0 基线）：

```text
Status:  PASS_VERIFIED
Build:   SKIPPED (Reveal deck: build check deferred to Phase 4)
  - scores_to_weights: ... declared=68.0s, real=NOT_VERIFIED
EXIT=0
```

**根因**：

1. 单一状态把“无 issues”当成“已验证”，没有运行时/人工/录制维度。
2. warnings 不参与退出码；`--strict` 只改变哪些检查进 issues，不改变 warning 的阻断性。
3. Reveal 路径没有 build/浏览器检查，`skipped` 没有映射为 `RUNTIME=NOT_RUN`。
4. Motion 无录像时 `real=NOT_VERIFIED` 只是 result 字段，不是 warning/issue。

**预期修复位置**（R2.3/R2.4，不在 R2.0 执行）：

- 状态聚合：`check-episode.py:830` 改为五维状态 + `stage_gate`；禁止静态检查输出 `PASS_VERIFIED`。
- 返回码：`check-episode.py:945` 改为 `FAIL=1` / `BLOCKED=2` / `CONTRACT_ERROR=3` / `PASS=0` / `NOT_APPLICABLE=4`。
- Motion：`check_motion_segment` 在无录像/无 probe 时产出 `RUNTIME=NOT_RUN`，并进入 blocked。
- Reveal：`build_info["skipped"]` 映射为 `RUNTIME=NOT_RUN`（course 需要 runtime）或 `NOT_APPLICABLE`（仅当模式明确不需要，且有批准）。
- Recording：cue 缺失在 `package`/`qa.static` 应为 ERROR，不是 warning。
- Handoff：迁移到 `episode.json` 后，缺失状态文件应为 `CONTRACT_ERROR`，不是 warning。
