## D-01 — 仓库拓扑

- **当前事实**：文档写“每课独立仓库、根仓库只跟踪框架”，但实际没有课程嵌套 `.git`；根仓库跟踪 `courses/transformer-self-attention/` 的 41 个文件；`new-episode.ps1` 不执行 `git init`。R0/R1 已记录该矛盾。
- **建议**：根仓库白名单，课程按 `courses/<course-id>/` 组织；暂不采用 submodule。
- **理由**：迁移成本最低；保留现有历史；CI 与备份路径不变；submodule 可在课程数量增长后再逐个引入。
- **影响**：根仓库体积随课程增长；需要维护“哪些课程被跟踪”的白名单；CI 需要明确课程 fixture 范围。
- **风险**：课程历史与框架历史混在一起；未来拆分需要 `git subtree split`；大型媒体可能误入根仓库。
- **验证条件**：`git rev-parse --show-toplevel` 在课程目录返回根仓库；`.gitignore` 白名单与 CI 一致；`git status --ignored` 不出现未预期的课程文件。
- **可逆性**：高。可随时拆分为独立仓库或 submodule。
- **批准状态**：`PENDING_OWNER_APPROVAL`。

## D-02 — Reveal 与 Slidev 的职责边界

- **当前事实**：`course` 使用 Reveal 6.0.2；`technical`/`news` 设计为 Slidev 53.0.0；Reveal 路径 strict QA 跳过 build；Slidev 路径 strict QA 会实际 build。
- **建议**：保持双轨，共用契约；不批量转换现有课程。
- **理由**：两种运行时都已安装/可复现；批量转换会引入内容与视觉回归；契约可把 `deck_kind` 作为适配器字段。
- **影响**：两套模板、两套 QA 分支、两套视觉规范；需要明确 `course`/`technical` 的默认与例外。
- **风险**：文档/检查漂移；用户混淆模式；双轨维护成本。
- **验证条件**：两种路径各有一个 fixture；`deck_kind` 决定检查分支；strict QA 对两种路径分别给出真实 build/浏览器证据。
- **可逆性**：中。统一到一套需要迁移课程与 QA。
- **批准状态**：`PENDING_OWNER_APPROVAL`。

## D-03 — Motion Canvas 主路径与 Manim 可选定位

- **当前事实**：Motion 3.17.2 + Vite 5.4.21 已安装；真实课程有 68s 段落；Manim 0.22.0 文档声明但当前未安装；无活跃课程 `.venv`。
- **建议**：Motion 为主路径；Manim 保留为可选 adapter，不作为默认依赖。
- **理由**：Manim 当前不可运行；旧课程仍引用；保留 adapter 可避免破坏历史对照。
- **影响**：Manim 场景需要显式安装；`engine=manim` 未安装时必须是 BLOCKED，不能是 NOT_APPLICABLE。
- **风险**：安装/版本漂移；旧课程无法直接重建；用户误以为 Manim 已可用。
- **验证条件**：`manim --version` 探测；`engine=manim` 的 fixture 在未安装时 BLOCKED；安装后单场景 ≤20s 且 ffprobe 通过。
- **可逆性**：高。可按课程启用/禁用。
- **批准状态**：`PENDING_OWNER_APPROVAL`。

## D-04 — Skill 的仓库内版本控制与分发

- **当前事实**：`course-studio`、`research-to-course-synthesis` 只在 `~/.claude/skills`；仓库内只有 `motion-isolation`/`manim-isolation`；`motion-isolation` 未注册；`manim-isolation` 已注册；`paper-search` 是 junction。
- **建议**：生产必需 Skill 优先 vendored 到仓库，记录 commit/来源/许可证/hash；许可证不允许时使用固定版本外部依赖 + `skills.lock`。
- **理由**：干净环境可复现；版本可审计；不依赖用户级配置；符合 R1“主路径必须可复现”的目标。
- **影响**：仓库增加 Skill 副本；需要安装脚本/junction；需要许可证审查；Windows junction 与其他平台需要替代。
- **风险**：许可证兼容性；Skill 副本与上游漂移；用户级配置冲突；`motion-isolation` 仍未注册。
- **验证条件**：空 `HOME`/新用户配置下按文档安装；`skills.lock` 哈希匹配；`motion-isolation` 出现在可用列表；许可证清单完整。
- **可逆性**：高。可改回外部 pinned 依赖。
- **批准状态**：`PENDING_OWNER_APPROVAL`。

- **建议**：确认 Claim Ledger v1 的 15 字段；退役“Core 14”；真实课程按 `migration-map.md` 迁移。
- **理由**：15 字段是唯一有完整字段列表、真实样本表头和 Skill 定义支持的版本；8 列缺证据/验证/冲突状态。

- **风险**：人工补状态可能不完整；迁移可能暴露未解决证据；不能自动填 `DIRECTLY_SUPPORTED`。
- **验证条件**：Schema 校验 + 迁移 dry-run + 14 条逐条人工状态 + 旧/新双跑；缺字段/坏枚举/无来源 fixture 失败。

## D-06 — 课程状态模型

- **当前事实**：旧 `check-episode.py` 在 `Build: SKIPPED`、`real=NOT_VERIFIED` 时仍输出 `PASS_VERIFIED` 且 exit 0；warnings 不阻断。
- **建议**：采用 STRUCTURAL / RUNTIME / HUMAN / RECORDING / DELIVERY 五维状态；单一 `PASS_VERIFIED` 退役。
- **理由**：能表达“结构通过但运行时未跑”“运行时通过但人未验收”；规则可机器判定；避免假绿。
- **影响**：checker 输出、handoff、CI、文档、退出码都需要改；旧状态需要兼容映射。
- **风险**：迁移期双状态混乱；旧工具/脚本依赖 `PASS_VERIFIED`；需要明确 warning 阻断策略。
- **验证条件**：五维 gate 伪代码 + 10 个边界案例 + 故障注入；`PASS_VERIFIED` 不再由静态检查输出。
- **可逆性**：高。保留旧输出作为兼容字段。
- **批准状态**：`PENDING_OWNER_APPROVAL`。

## D-07 — 运行时 QA 的执行范围

- **当前事实**：Reveal 路径无构建/浏览器检查；Motion 无 typecheck/probe gate；Slidev 只在 strict QA 的 technical/news 路径 build；Playwright 未安装；Chrome/Node/pnpm/ffmpeg 可用。
- **建议**：纳入真实运行时 QA：Motion typecheck + probe、Reveal 静态服务 + 浏览器加载、Slidev build；逐页截图/视觉 diff 归 L3 人工。
- **理由**：覆盖最危险的编译/加载/时长问题；成本可控；不依赖 Playwright。
- **影响**：CI 需要 Node/pnpm/Chrome；运行时 job 可能不稳定；证据落盘与保留期。
- **风险**：浏览器 flakiness；CI 时间；Chrome 版本差异；截图存储。
- **验证条件**：L2 正向 fixture + 类型错误/缺资源/坏 probe 故障注入；证据路径/哈希记录；失败不写 PASS。
- **可逆性**：高。按 stage/job 开关。
- **批准状态**：`PENDING_OWNER_APPROVAL`。

## D-09 — CI 分层

- **当前事实**：CI 只做 py_compile、链接检查、32 项回归；run `40319878317` 成功；不跑真实课程、不构建、不渲染。
- **建议**：L1 必跑；受影响组件的 L2 必跑；完整 clean-room 验证独立执行（可手动/定时）。
- **理由**：L1 快且稳定；L2 需要 Node/Chrome，适合按变更路径触发；clean-room 成本高，独立执行。
- **影响**：workflow 需要路径过滤/缓存；L2 可能增加 5–15 分钟；需要明确失败是否阻断合并。
- **风险**：L2 flakiness；缓存污染；CI 资源；未批准的依赖安装。
- **验证条件**：坏 fixture 使 CI 失败；L2 可手动触发；L1 在 2 分钟内；clean-room 有独立记录。
- **可逆性**：高。
