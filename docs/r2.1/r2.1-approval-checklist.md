> 实施基线：`ADOPTED_FOR_R2_1_IMPLEMENTATION`；负责人批准：`PENDING_OWNER_APPROVAL`。这是工程实施基线，不是负责人签署的批准记录。
>
> 本文件用于确认 R2.1 的产品目标、架构决策、自动化质量门禁与实施边界。本文中的“推荐决定”是待项目所有者确认的建议，不代表已经获得批准。
>
> 核心原则：**自动化生产、独立验证、证据可追溯、失败不掩盖、人工审核非必需。**

## 0. R2.1 的核心产品目标

CourseStudio 的主要目标是稳定地产出可用于制作高质量视频课程的完整交付包，而不是仅生成文档、代码或通过测试。

课程可以由多个课件页面和独立动画片段组成。用户可以自行录屏、配音、拼接，不要求系统必须自动完成最终视频制作。

### 0.1 每个完整课程包的预期交付物

- [ ] `episode.json` 或等价的统一课程清单：记录课程元数据、章节、片段、资源、工具适配器和检查状态。
- [ ] 研究与证据包：来源、原始链接、定位信息、关键主张、证据对应关系、不确定性及来源冲突。
- [ ] 课程大纲与分段设计：学习目标、目标受众、知识依赖、章节顺序、节奏和每段教学目的。
- [ ] 逐段讲稿：旁白、预计时长、段落边界、术语说明及与画面或动画的同步提示。
- [ ] 可播放的 HTML 课件或 PPT 风格视觉材料：版式一致、文字清晰、适合录屏。
- [ ] 独立动画片段：能够单独构建、渲染或探测，包含画幅、帧率、时长和输入资源声明。
- [ ] 素材包：SVG、图表、图片、数据、字体及其他资源的来源、许可和生成方式。
- [ ] 制作衔接材料：片段顺序、旁白对应关系、录制提示、转场与拼接说明。
- [ ] 自动 QA 报告：检查项、工具与版本、实际命令、退出码、证据、失败、跳过项和未验证事项。
- [ ] 交付清单：文件路径、哈希、依赖、复现步骤和已知限制。

最终录制视频不是默认必需交付物。只有任务明确要求生成最终视频时，才将编码、音视频同步、帧率和文件完整性列为必需检查。

### 0.2 内容与视觉质量目标

- 事实主张可以追溯到来源；不得伪造引用、研究结果或验证记录。
- 讲稿与课件、动画在概念、顺序和术语上保持一致。
- 动画用于解释知识，而不只是添加装饰性转场。
- 视觉层级、文字密度、图表标注和画面留白适合教学与录屏。
- 每个片段的声明时长与实际探测结果一致，或明确报告偏差。
- 所有必要资源均存在，路径有效，许可信息齐全或明确标注未知。
- 自动化检查结果能够对应到具体文件、片段、主张和失败原因。

### 0.3 自动化验收原则

1. 不设置强制人工审核步骤。
2. 生成与验证尽可能使用不同工具、不同执行路径或不同模型。
3. 事实验证优先依赖原始来源和可定位证据，而不是模型之间的一致意见。
4. 代码与资源验证优先依赖真实执行、构建、渲染和文件检查。
5. 视觉质量检查使用实际渲染产物，不只检查源代码。
6. 未执行的检查不得标记为通过；工具不可用不得伪装成不适用。
7. AI 自检失败时，优先自动修复并重跑；仍然无法解决时，输出具体阻塞原因和可供所有者决定的选项。
8. 用户可以直接接受结果、拒绝结果或要求返工，不必逐项审核报告。

## 2. 质量状态定义

不允许将所有状态压缩成一个笼统的 `PASS_VERIFIED`。

| 维度 | 含义 | 通过条件 |
|---|---|---|
| `STRUCTURAL` | 结构与契约 | Schema、必要文件、引用关系、资源路径和清单校验通过 |
| `RUNTIME` | 实际运行 | 所有适用的构建、浏览器加载、类型检查、渲染或探测均有实际执行证据 |
| `CONTENT_QUALITY` | 内容与视觉质量 | 自动内容检查、证据检查、讲稿与画面一致性检查及视觉检查达到项目阈值 |
| `RECORDING` | 录制与拼接 | 若任务要求最终视频，则验证实际视频；若只交付制作包，则标为 `NOT_APPLICABLE` 并记录范围 |
| `DELIVERY` | 最终交付 | 必需产物齐全、哈希与清单完整、依赖及已知限制明确，且不存在未解决的强制阻塞项 |

每个维度使用明确状态，例如：

- `PASS`：必需检查实际运行并满足标准。
- `FAIL`：检查实际运行，但结果不满足标准。
- `BLOCKED`：必需检查无法执行，或依赖缺失。
- `PARTIAL`：部分检查通过，仍有未解决事项。
- `NOT_RUN`：尚未执行。
- `NOT_APPLICABLE`：根据已声明的任务范围确实不适用。

`NOT_APPLICABLE` 必须有适用范围说明，不可用来规避失败。`DELIVERY=PASS` 的前提是所有必需维度满足交付条件。

## 3. AI 多工具交叉自检要求

### 3.1 内容与证据

- 生成工具输出主张与来源候选。
- 独立检索或核验步骤检查原始来源是否存在、是否相关、定位是否准确。
- 证据检查区分直接支持、间接支持、矛盾、证据不足和未核实。
- 模型判断只能作为检查意见，不可代替实际来源证据。
- 无法核实的主张应标记为待处理、降低确定性或从交付内容中删除。

### 3.2 代码与结构

- 对适用的 JSON Schema 执行完整标准验证。
- 执行契约测试、资源路径检查、相对链接检查和敏感信息扫描。
- 对实际选用的动画和课件适配器运行对应的类型检查、构建、浏览器加载或渲染探测。
- 记录真实命令、退出码、工具版本和输出文件位置。

### 3.3 视觉与讲稿

- 基于实际渲染页面或截图检查文字溢出、遮挡、对齐、对比度、图表标注和版式一致性。
- 检查讲稿分段与页面、动画片段之间的映射。
- 检查动画的关键状态、知识解释顺序和声明时长。
- 对自动视觉检查无法可靠判断的项目，明确记录能力限制，不得宣称已验证。

### 3.4 交叉检查与冲突处理

- 对高风险事实和重要技术结论使用独立验证路径。
- 对模型或工具之间的冲突保留各自结果、证据与判断理由。
- 优先使用权威原始来源、确定性程序检查和实际运行结果解决冲突。
- 若冲突仍无法解决，标记 `BLOCKED` 或 `PARTIAL`，并提供可供项目所有者选择的解决方案。

## 4. L1 / L2 / L3 自动化门禁

### L1：结构检查

包括：

- Schema 和接口契约。
- 必需文件、路径和引用关系。
- 资源存在性、链接和许可记录完整性。
- 主张、片段、讲稿与课件的关联结构。
- 敏感信息与本地绝对路径扫描。
- 单元测试和契约测试。

### L2：实际运行检查

只针对实际使用或受影响的组件执行，但不得跳过本次交付必需的组件。

- Motion Canvas：类型检查，以及真实渲染或可验证的运行探测。
- Reveal：实际浏览器加载与必要的交互或布局检查。
- Slidev：实际构建与必要的浏览器加载检查。
- Manim：只有课程声明使用 Manim 时，才要求相应环境和运行检查。
- 资源生成：检查实际输出文件、尺寸、格式和依赖。

如果某个必需组件缺少环境或工具，结果应为 `BLOCKED`。只有在组件确实不属于当前课程交付范围时，才能标记 `NOT_APPLICABLE`。

### L3：自动化内容与视觉质量检查

- 事实主张与证据关联完整性。
- 讲稿与画面映射完整性。
- 页面文字密度、溢出、遮挡、视觉一致性。
- 动画关键状态、时长和片段衔接。
- 课程包完整性、已知风险和交付清单一致性。

L3 不要求人工签字，但必须公开自动化方法、覆盖范围和已知盲区。

## 6. 端到端验收

R2.1 不能仅凭测试通过、文档齐全或目录创建成功而验收。

代表性课程必须实际生成完整交付包，并完成：

- [ ] 研究与证据包生成。
- [ ] 大纲、逐段讲稿和视觉分段生成。
- [ ] HTML 课件实际构建和加载。
- [ ] 动画片段实际生成、渲染或探测。
- [ ] 资源、来源、许可和文件清单检查。
- [ ] 自动化内容、证据、视觉和一致性检查。
- [ ] 自动返工后重新执行相关检查。
- [ ] 输出完整 QA 报告、Trace 报告与交付清单。
- [ ] 所有未运行、失败、受限和不确定的检查均如实记录。

最终报告必须明确区分：

1. 已通过的检查及其证据。
2. 实际失败的检查。
3. 因环境或依赖而阻塞的检查。
4. 尚未执行的检查。
5. 自动化无法可靠判断的事项。
6. 仍需项目所有者决定的取舍。
