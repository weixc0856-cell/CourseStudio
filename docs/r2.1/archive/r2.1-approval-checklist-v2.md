## 1. 最终产品目标与验收基线

### 1.1 CourseStudio 必须交付什么

CourseStudio 的核心任务是：在 Claude Code 和相关制作工具的辅助下，将一个课程主题转化为可以分段制作、录制、配音、拼接和持续维护的视频课程。

| 成品 | 必需交付内容 | 验收标准 |
|---|---|---|
| 课程结构 | 课程目标、受众、章节、知识顺序、每段目标 | 结构完整，章节之间有明确的逻辑关系 |
| 动画 | 可运行的动画源文件和可复现的运行方式 | 实际运行通过；关键视觉变化、公式或图形推导符合脚本 |
| 可视化课件 | 可全屏展示的 HTML 或等效演示页面 | 页面可打开、布局完整、字体和资源正常、无明显溢出或遮挡 |
| 口播稿 | 与片段、镜头和课件对应的讲解稿 | 能定位到具体片段；讲解顺序与视觉展示一致 |
| 研究与支撑材料 | 来源清单、证据、公式/数据核对记录、素材来源 | 重要事实可追溯；不把未经核验的内容写成已验证事实 |
| 片段清单 | 片段 ID、顺序、目标时长、输入输出、依赖关系 | 可以独立制作、单独检查，并按清单拼接 |
| 录制包 | 录制说明、分段清单、配音对应关系、文件校验信息 | 人可以依照说明完成录屏、配音和拼接 |
| QA 与交付报告 | 结构、运行时、人工验收、录制和交付状态 | 明确区分已验证、部分验证、未运行、失败和不适用 |

### 1.2 关键产品原则

1. **最终成品优先于工具栈。** 不因当前已安装某个工具，就强制所有课程采用该工具。
2. **动画与口播必须对齐。** 每个片段需要明确“画面展示什么、讲解什么、两者如何对应”。
3. **允许分段生产。** 不要求一次生成完整长视频；每个片段可以单独制作、验收和返工。
4. **自动检查不等于视觉验收。** 构建通过只能证明部分工程条件满足，不能证明动画质量、讲解清晰度或视觉效果达标。
5. **证据必须真实。** 没运行的检查不能标为通过；缺少浏览器、渲染或录制证据时必须明确标记。
6. **允许人工参与。** 人工审阅、录屏、配音和最终拼接可以保留，但必须有明确输入、操作步骤和验收标准。
7. **先验证代表性课程，再扩大迁移。** 不能只凭文档、Schema 或测试夹具证明整个生产流程可用。

### 1.3 产品级验收标准

R2.1 及后续阶段应至少用一个真实课程或有代表性的课程章节验证完整链路：

`研究 → 大纲 → 分段脚本 → 课件/动画 → 口播稿 → 运行检查 → 人工验收 → 录制包`

验收时必须能够回答：

- 课程是否真的讲清了目标知识，而非只生成看起来完整的内容？
- 重要事实、公式、数字和引用是否能追溯到来源？
- 动画是否表达了脚本要求的视觉变化，而不只是能够播放？
- 课件与口播是否逐段对应？
- 每段是否能独立重做，且不会破坏其他片段？
- 新环境能否按说明恢复依赖并重建成品？
- 交付报告是否如实说明未验证项和人工待办？

**不得用契约测试通过、链接检查通过或静态 QA 通过，替代上述产品级验收。**

## 3. D-07 运行时与成品 QA 规则

### 3.1 检查层级

| 层级 | 检查内容 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| L1：结构与契约 | Schema、文件存在、引用、链接、资源清单、命名 | 项目结构满足规则 | 动画能够运行或视觉效果正确 |
| L2：真实运行 | 引擎构建、浏览器加载、动画 probe、时长和媒体检查 | 对应运行路径实际可执行 | 课程讲解一定正确、视觉设计一定优秀 |
| L3：内容与视觉人工验收 | 事实与公式、叙述连贯性、画面清晰度、节奏、口播与画面对齐 | 成品是否满足课程质量要求 | 未覆盖片段的质量 |
| L4：交付与复现 | 录制包、哈希、依赖锁定、干净环境重建、交付清单 | 成品可交接、可追溯、具备复现条件 | 未来所有机器和环境均绝对不会出现差异 |

### 3.2 运行时适用规则

| 组件 | 必须执行的检查 | 不允许的替代 |
|---|---|---|
| Motion Canvas 动画 | 对应 TypeScript 类型检查、实际构建/运行、代表片段 probe；必要时验证帧数与时长 | 只检查源代码存在 |
| Reveal 课件 | 实际加载页面、检查资源与控制台错误、验证页面内容可见 | 仅检查 HTML 文件存在 |
| Slidev 课件 | 实际 build、检查构建产物，并验证浏览器展示 | 只运行静态链接检查 |
| Manim 动画 | 仅当课程选择 Manim 时，验证依赖、渲染和输出媒体 | 引擎未安装却报告“不适用” |
| 最终录制媒体 | 文件存在、大小、哈希、ffprobe 信息及必要抽帧检查 | 只检查录制命令退出码 |
| 人工录屏与配音 | 检查片段顺序、口播对应关系、音画问题和最终交付状态 | 用自动构建结果代替人工验收 |

以上为建议的能力要求；具体命令、浏览器和工具版本应在实现阶段依据实际环境锁定。

### 3.3 跳过、失败和证据规则

1. 检查结果至少区分 `PASS`、`FAIL`、`BLOCKED`、`PARTIAL`、`NOT_APPLICABLE` 和 `NOT_RUN`。
2. `NOT_APPLICABLE` 必须有适用性规则作为依据；工具缺失不能自动视为不适用。
3. 必需检查未执行时，相关维度必须为 `BLOCKED` 或 `NOT_RUN`，不得输出整体交付通过。
4. 检查失败时必须保留失败命令、退出码、日志和输入版本信息。
5. 对运行时检查的豁免必须记录范围、理由、批准人和时间；豁免不能伪装成通过。
6. 运行证据应关联到具体课程、片段、输入哈希和工具版本。
7. 缺少截图、probe 或其他必需证据时，应明确标记证据缺口，不得生成虚构的验证结果。
8. 人工视觉验收必须记录实际检查的片段或页面范围，不得把抽样验收描述成全量验收。

### 3.4 必需证据

| 检查 | 最低证据 |
|---|---|
| 动画类型检查 | 命令、退出码、日志、工具版本、输入文件标识 |
| 动画实际运行 | 运行或渲染结果、片段 ID、帧率/帧数/时长信息、必要截图 |
| 课件浏览器检查 | 加载结果、资源错误与控制台异常、页面或片段范围、必要截图 |
| 课件构建 | 命令、退出码、构建日志、产物路径、工具版本 |
| 内容审核 | 主张/公式/数据核验记录、来源定位、审核状态和未决问题 |
| 录制交付 | 文件清单、大小、SHA-256、媒体探测信息、必要抽帧及人工验收记录 |

## 4. D-09 测试分层与变更影响

| 变更范围 | L1 必跑 | L2 必跑条件 |
|---|---|---|
| 动画源代码、片段定义、时长配置 | Schema、引用和结构检查 | 对应动画引擎类型检查、构建/运行和时长验证 |
| HTML 课件、Slidev/Reveal 页面、视觉资源 | 结构、资源、链接、溢出风险检查 | 对应课件引擎 build 和浏览器检查 |
| 研究内容、口播稿、公式和数据 | 引用、来源、锚点、结构与一致性检查 | 仅在影响动画/课件行为时执行相应运行时检查；内容审核仍须按风险执行 |
| 片段顺序、录制清单、媒体文件 | 清单、引用和顺序检查 | 涉及媒体变更时执行媒体探测；最终交付按范围验收 |
| Schema、契约和测试代码 | 契约测试、Schema 自身验证、链接与敏感信息扫描 | 验证受影响的消费者；不能只验证 Schema 文件本身 |
| CI、QA 工具和脚手架 | 单元测试、语法检查、契约与链接检查 | 对受影响生产路径执行集成测试 |
| 纯文档变更 | 链接、敏感信息及必要的格式检查 | 通常不需要浏览器或渲染测试 |

规则：

1. L2 按真实依赖和变更影响执行，不要求每次无差别重跑所有引擎。
2. 不能因路径过滤未识别出变更，就跳过实际受影响的检查。
3. L2 失败默认阻断交付；是否阻断合并应在 CI 规则中明确。
4. clean-room 验证独立记录，不能替代当前变更必需的 L2。
5. 每类检查应有正向样例和至少一个对应的失败样例。
6. CI 的成功状态不得覆盖课程自身 `RUNTIME`、`HUMAN` 或 `RECORDING` 尚未完成的事实。

### 5.1 JSON Schema 验证器要求

- 使用项目级、可锁定的独立环境；不依赖某台机器的全局安装。
- 采用固定版本的 `jsonschema`，记录完整依赖锁定文件。
- 验证 Draft 2020-12 Schema 元数据与实际数据实例。
- 覆盖有效样例、缺字段、错误类型、非法枚举、错误引用和边界值。
- 保留 `mini_schema.py` 作为必要时的轻量辅助工具也可以，但不得宣称它等价于完整 Draft 2020-12 验证。
- CI 使用锁定依赖进行可复现安装和检查。
- 依赖引入前检查许可证与维护风险。

### 5.2 R2.1 范围限制

R2.1 首先完成契约验证、只读 shadow 数据、旧新 checker 对照和失败行为验证。

未经单独授权，不得：

- 自动覆盖真实课程文件；
- 批量迁移课程内容或删除旧格式；
- 将未核验的研究主张标记为已证实；
- 直接把生产 checker 的旧状态改成新状态而不保留对照证据；
- 以文档完成或测试夹具通过宣称整个课程生产系统已验收；
- 自动提交、推送、合并或创建 PR。

## 6. 风险与停止条件

遇到以下情况应停止推进相关阶段，并报告具体原因：

- 备份清单不完整、哈希不一致或关键文件无法恢复；
- Schema 验证器没有真正执行完整验证；
- 旧新 checker 的结果不一致且原因未查明；
- 必需运行时检查被跳过，却仍被判定为通过；
- 课程、动画、口播或录制清单之间出现无法解释的映射错误；
- 研究来源无法追溯，或重要事实、公式和数据存在未处理冲突；
- 未经批准的内容覆盖、批量迁移或删除；
- 依赖当前用户级 Skill、未记录的本地路径或未锁定的工具版本才能运行。
