## 2. 现行质量保障政策

### 2.1 取消强制人工审核

课程生产流水线不设置人工逐项审核、人工签字或人工确认每个 QA 节点的强制门槛。

默认流程为：

1. AI 生成课程内容和相关产物。
2. 调用适用的工具执行独立检查。
3. 汇总证据、检查结果和工具间冲突。
4. 对可自动修复的问题执行定向返工。
5. 对受影响的检查重新运行。
6. 输出最终质量报告和交付状态。

项目负责人保留最终接受或拒绝交付结果的权利，但不需要逐项审核日常产物。

**负责人对架构决策的批准与课程内容的人工审核是两件不同的事。** 前者可以作为项目启动的治理条件，后者不作为课程生产的强制质量门禁。

### 2.2 状态维度

统一使用以下五个维度：

| 维度 | 检查对象 |
|---|---|
| `STRUCTURAL` | Schema、契约、文件结构、引用关系和资源完整性 |
| `RUNTIME` | 实际构建、浏览器加载、代码运行、动画渲染和输出探测 |
| `CONTENT_QUALITY` | 事实证据、讲稿一致性、教学结构、视觉质量和自动化交叉检查 |
| `RECORDING` | 实际录制与拼接；是否必需取决于交付范围 |
| `DELIVERY` | 交付包完整性、可复现性、检查证据和未解决阻塞项 |

各维度必须独立记录结果，不得以某一维度通过推导整个课程包通过。

### 2.3 AI 多工具交叉自检

交叉自检必须尽可能使用不同的验证机制，而不是让同一个模型重复评价自己的输出。

- **事实与引用：** 检查原始来源、具体定位和主张支持关系。
- **代码与契约：** 使用 Schema 验证器、测试程序和实际执行结果。
- **课件与动画：** 执行真实构建、浏览器加载、渲染或探测，并检查实际产物。
- **视觉质量：** 基于真实渲染页面或截图检查布局、溢出、遮挡、文字密度和图表标注。
- **讲稿与画面：** 检查分段映射、术语一致性、动画步骤和声明时长。
- **工具间冲突：** 保留各工具结果，优先通过原始来源、确定性检查或实际运行证据解决。

模型之间意见一致不能单独证明事实正确；静态检查通过也不能替代实际运行。

### 2.4 自动返工与异常处理

`NEEDS_REVIEW` 不意味着必须交给人工审核。应先尝试自动返工，并对修改影响到的检查重新执行。

| 情况 | 处理方式 |
|---|---|
| 可自动修复的结构或格式问题 | 自动修复并重跑相关检查 |
| 事实证据不足 | 重新检索、收窄表述或删除不可靠主张 |
| 构建或渲染失败 | 定位失败组件，修复并重新运行 |
| 工具之间存在冲突 | 保留证据，执行独立复核；无法解决时标记 `BLOCKED` 或 `PARTIAL` |
| 必需工具不可用 | 标记 `BLOCKED`，不得宣称通过 |
| 检查尚未执行 | 标记 `NOT_RUN` |
| 当前任务确实不需要某组件 | 标记 `NOT_APPLICABLE` 并记录适用范围 |
| 自动化能力无法覆盖某项判断 | 记录能力限制与剩余风险，不得伪称已验证 |

负责人只需在最终交付时决定接受或拒绝，或在自动化无法解决且确实涉及产品取舍时提供决策。

## 5. R2.1 启动判定

**当前结论：`BLOCKED`。**

阻塞原因是生产实现与验证证据尚未达到启动条件，而不是因为取消了人工审核。

| 阻塞项 | 解除条件 |
|---|---|
| D-01 至 D-12 尚未确认 | 负责人确认架构决策，或明确登记暂缓项及其影响 |
| 完整 Schema 验证未就绪 | 验证器和依赖锁定完成，并实际运行标准验证 |
| 最新设计成果未进入新快照 | 重新生成覆盖当前文件集的快照，并校验文件清单与哈希 |
| 完整恢复演练未执行 | 完成独立位置的恢复验证 |
| 真实课程端到端未执行 | 生成完整课程包并运行必需的 L1、L2、L3 检查 |
| 生产 checker 存在假绿风险 | 修复状态判定逻辑，并用故障注入证明未验证、失败和阻塞状态不会错误通过 |
| Schema 仍保留历史 `HUMAN` 字段 | 完成契约迁移、兼容策略和相关测试 |

R2.1 的具体启动范围可以在上述事项关闭后确认。若某项暂缓不影响本次实际范围，应记录依据和风险；不能将必需检查未运行的情况直接视为通过。

## 6. 建议执行顺序

1. **冻结当前状态：** 记录 HEAD、工作区和 54 个未跟踪文件，核对清单。
2. **更新备份：** 将最新权威文档和相关设计文件纳入新快照，执行哈希校验。
3. **确认架构决策：** 负责人确认 D-01 至 D-12，允许明确记录暂缓项。
4. **修复假绿：** 先确保检查器准确区分通过、失败、阻塞和未执行。
5. **完善验证工具：** 完成完整 Schema 验证和依赖锁定。
6. **实施契约迁移：** 更新状态模型、Schema 和兼容逻辑，取消新流程中的强制 `HUMAN` 门禁。
7. **真实课程试产：** 执行完整生成、自动交叉自检、自动返工和复验。
8. **干净环境复现：** 验证依赖恢复、构建、渲染和报告生成。
9. **形成启动报告：** 仅依据实际执行证据更新各状态，确认 R2.1 是否具备启动条件。

## 7. 最终结论

CourseStudio 的目标是通过 AI 与工程工具的交叉自检，稳定生成完整、可复现、可追溯的视频课程制作包。

**取消人工审核不代表降低验证标准，也不代表允许 AI 自行宣布通过。**

R2.1 应在生产检查器不再存在假绿风险、必需验证工具可用、真实课程端到端试产完成且关键阻塞项关闭后，才进入正式实施阶段。

本报告中的待执行事项继续保持 `NOT_RUN` 或 `BLOCKED`，直到实际执行产生可复核证据。
