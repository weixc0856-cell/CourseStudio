## M1 — 为什么需要混合不同位置的信息

### Slide 01 — 一个 token 不该只看自己

[SLIDE: 01]

**画面**：标题页。大字写出“一个 token 的含义，为什么要参考其他位置？”下方留一个简单的序列示意：四个小方块 `t1 t2 t3 t4`，其中一个被高亮。

**口播**：

我们先从一个问题开始：处理一句话里的某个词时，它应该只由自己的向量决定吗？

假设句子里的一个词本身很模糊，比如“它”。只看“它”这个 token，很难知道它指的是什么；但同一句里其他位置的信息，可能正好能帮上忙。

Self-attention 想解决的，就是这件事：让每个位置在处理自己时，能参考同一序列里的其他位置，而不是各看各的。

（依据：CLM-001、CLM-002、CLM-003；内部备注，不口播。）

### Slide 02 — Attention 要解决的问题

[SLIDE: 02]

**画面**：左边画四个 token；右边画一个“当前 token”的框，向外发出几条虚线箭头，指向其他 token。箭头暂不标数字，只表示“可以去看”。

**口播**：

所以，attention 要回答的不是“整句是什么意思”，而是：当前这个位置，应该从其他位置取多少信息？

它仍然为每个位置保留一个输出；只是这个输出不再只由自己决定，而是把别处的内容按相关性混进来。

这集我们只追两个问题：第一，Q、K、V 三个角色分别是什么；第二，query 和 key 怎样比较，比较结果又怎样分配信息。

先不急着写公式。先把“谁在找、谁被找、谁被取用”这三件事分清楚。

（依据：CLM-001、CLM-003、CLM-004；内部备注，不口播。）

## M2 — Q/K/V 三个角色

### Slide 03 — Query、Key、Value 各做什么

[SLIDE: 03]

**画面**：三列卡片。左列 Query，写“我在找什么”；中列 Key，写“我能提供什么”；右列 Value，写“我实际被取用的内容”。下方画一个“当前 token 的 query”与四个 key 比较，再把匹配结果落到对应的 value 上；不写数字。

**口播**：

先给一个有用的直觉：Query 像当前 token 发出的“匹配请求”，Key 像每个 token 摆出来的“可匹配信息”，Value 才是真正被聚合、被带走的内容。

形式上，attention 会拿当前 query 和所有 key 做兼容性比较，再根据比较结果去取对应的 value。所以，query 决定“和谁匹配”，value 决定“最后混进来的是什么”。

注意，这里说的是三个角色，不是三个不同的输入来源。它们是从同一段输入里得到的三种表示。

（依据：CLM-001、CLM-003；CLM-004 是教学直觉，内部备注，不口播为原文定义。）

### Slide 04 — Self-attention：Q/K/V 同源

[SLIDE: 04]

**画面**：一个输入序列 `t1 t2 t3 t4` 指向三个并排的表示块：Q、K、V；三个块都从同一排 token 出发。旁边一句边界说明：“单头可看作同一输入的不同投影；本集不展开投影矩阵。”

**口播**：

在 self-attention 里，Q、K、V 有一个关键共同点：它们来自同一个地方——同一个输入序列。不是 query 来自一句话、key 来自另一句话；而是同一排 token 各自提供 query、key、value 三种角色。

单头情况下，你可以把 Q、K、V 理解成同一输入的不同投影。但这个投影矩阵本集不展开；我们只需要记住：它们同源，角色不同。

角色分清之后，下一步才是算分数：当前 query 和每个 key 到底有多匹配。那会是下一批模块的内容。

（依据：CLM-002、CLM-011；CLM-011 是 secondary pedagogical framing，内部备注，不口播为 S01 单头定义。）

## M3 — Score：query 与 key 的点积

### Slide 05 — 一行 query 对所有 key 打分

[SLIDE: 05]

**画面**：左侧放 toy 的一组行向量：`q1=[3,0,0,0]`；右侧并排列出四个 key：`k1=[2,0,0,0]`、`k2=[0,2,0,0]`、`k3=[0,0,2,0]`、`k4=[0,0,0,2]`。每个 key 旁边标出它和 `q1` 的点积结果：`6, 0, 0, 0`。不出现 softmax。

**口播**：

角色分清之后，开始算分数。score 的来源很直接：拿当前 query 和每一个 key 做点积。

在这个教学例子里，`q1` 和 `k1` 的点积是 6；和另外三个 key 的点积都是 0。先不管这些数字大不大，至少能看到：分数在告诉我们，当前 query 和哪个 key 更匹配。

这里先只得到分数，不急着做归一化。归一化是后面的步骤；现在只建立“query 对所有 key 打分”这件事。

（依据：CLM-005；toy 数字为 CLM-014 illustrative，内部备注，不口播。）

### Slide 06 — Score 矩阵 `S = QK^T`

[SLIDE: 06]

**画面**：把四个 query、四个 key 的分数排成 4×4 矩阵。行标 `q1..q4`，列标 `k1..k4`。高亮第 1 行 `[6,0,0,0]`，并标注“一行 = 一个 query 对所有 key 的分数”。

```text
S =
[ 6  0  0  0 ]
[ 0  4  2  0 ]
[ 2  2  2  2 ]
[ 0  0  2  4 ]
```

**口播**：

把每个 query 的分数并排放在一起，就得到 score 矩阵。它的形状是 4 乘 4：每一行对应一个 query，每一列对应一个 key。

看第 1 行：`q1` 对四个 key 的分数是 6、0、0、0。看第 3 行：`q3` 对四个 key 都是 2。分数大小不同，但这时候它们仍然只是分数，还没有被归一化。

矩阵写法就是 `S = QK^T`：`Q` 是 4 个 query，`K` 是 4 个 key，转置后相乘，得到 4 乘 4 的分数表。

（依据：CLM-005；S01 §3.2.1 p.4；toy 数字 CLM-014。）

## M4 — 缩放：为什么除以 √d_k

### Slide 07 — 分数先缩放，再谈归一化

[SLIDE: 07]

**画面**：左边显示 score 矩阵 `S`；右边显示缩放后的矩阵 `S/2`，因为 toy 里 `d_k=4`、`√d_k=2`。用箭头把第 1 行 `[6,0,0,0]` 指向 `[3,0,0,0]`。旁边用三张小卡片分别标 `FACT`、`CLAIM`、`INFERENCE`。

```text
scaled = S / √d_k = S / 2
[ 3.0  0.0  0.0  0.0 ]
[ 0.0  2.0  1.0  0.0 ]
[ 1.0  1.0  1.0  1.0 ]
[ 0.0  0.0  1.0  2.0 ]
```

**口播**：

在进入 softmax 之前，论文先做一步缩放：把每个分数除以 `√d_k`。这是方法本身，属于原文直接支持的做法。

toy 里 `d_k=4`，所以 `√d_k=2`；第 1 行的分数从 6、0、0、0 变成 3、0、0、0。缩放没有改变谁大谁小，只是把数值范围压小。

为什么这样做？论文给的理由是：当 `d_k` 很大时，点积容易变得很大，softmax 会被推到梯度很小的区域；除以 `√d_k` 可以缓解这个问题。注意，原文在这里用的是“We suspect”，这是一个理由陈述，不是已经被证明对所有模型都成立的普适定理。

脚注还给出了一个更具体的推导：如果假设 q 和 k 的各个分量独立、均值为 0、方差为 1，那么点积的方差是 `d_k`；维度越大，点积波动越大。这个推导依赖这些假设，属于脚注假设下的解释，也不能直接推广到所有真实分布。

所以这里分三层：除以 `√d_k` 是方法；论文的“大分数/小梯度”是它陈述的理由；脚注的方差推导是在特定假设下的解释。三层不要混成一句“已经证明必须这样做”。

（依据：CLM-006 FACT、CLM-007 CLAIM、CLM-008 INFERENCE；CLM-014 toy illustrative；内部备注，不口播。）

## M5 — 行 softmax：从分数到权重

### Slide 08 — 每一行分数变成一组权重

[SLIDE: 08]

**画面**：左边是缩放后的 score 矩阵 `S/2`；右边预留一个同样大小的权重矩阵 `A` 的轮廓。行标 `t1..t4`，列标 `k1..k4`。高亮第 1 行与第 3 行，先不给数字。

**口播**：

现在把缩放后的分数变成权重。关键动作是 softmax，而且要按行做：每个 query 自己的一行，和所有 key 的分数一起做 softmax。

做完之后，每一行会得到一组非负的权重，并且这一行的权重加起来是 1。换句话说，softmax 回答的是：当前这个 token，把多少注意力分给各个位置。

这里先按行看，不是把整张矩阵一起归一化。行是 query，列是 key；每一行有自己的分配。

下面的动画把这条路径走一遍：先看 score，再除以 `√d_k`，然后逐行 softmax，最后停在权重矩阵 A。

（依据：CLM-009；动画只到 A，不进入输出。）

### Slide 09 — 集中与均匀：两种权重形态

[SLIDE: 09]

**画面**：并列两张小表。左边 `t1` 行：`0.870, 0.043, 0.043, 0.043`；右边 `t3` 行：`0.250, 0.250, 0.250, 0.250`。用两根权重条长度对比；不画输出向量。

**口播**：

看两个对比。`t1` 这一行，`k1` 的权重约 0.870，另外三个 key 各约 0.043；注意力明显集中在第一个 key。`t3` 这一行，四个 key 都是 0.25，几乎是均匀分配。

这两种形态都来自同一套 score 和同一个 softmax；差别只在分数结构。分数差距大，softmax 后就更集中；分数相同，softmax 后就均匀。

注意，这里停在了权重矩阵 A。权重怎样作用到 value 上、输出长什么样，是下一个模块的内容；这个动画不替它收尾。

（依据：CLM-009；toy 数字 CLM-014 illustrative；不进入输出。）

## M6 — 输出：权重对 V 做加权和

### Slide 10 — 从权重矩阵 A 到输出 O

[SLIDE: 10]

**画面**：上方是权重矩阵 A 的两行高亮：`t1` 行 `0.870, 0.043, 0.043, 0.043`；`t3` 行 `0.250, 0.250, 0.250, 0.250`。右侧列出四个 value：`v1=[1,0]`、`v2=[0,1]`、`v3=[1,1]`、`v4=[2,0]`。下方显示 `O = A V`，并给出 `o1/o3`。

```text
o1 = 0.870·v1 + 0.043·v2 + 0.043·v3 + 0.043·v4
   ≈ [1.000, 0.0866]

o3 = 0.25·v1 + 0.25·v2 + 0.25·v3 + 0.25·v4
   = [1.000, 0.5000]
```

**口播**：

动画停在了权重矩阵 A。现在把最后一步接上：输出是什么？

答案不是再算一次分数，而是用每一行的权重，去对所有 value 做加权和。`t1` 这一行把 0.870 分给了 `k1` 对应的 `v1`，所以 `o1` 主要保留了 `v1` 的内容，只混入少量其他 value；算出来约等于 `[1.000, 0.0866]`。

`t3` 这一行四个权重都是 0.25，相当于对四个 value 取平均；`o3` 正好是 `[1.000, 0.5000]`。

所以，输出不是“整句的一个摘要”，而是每个位置各自得到一个向量：它由该位置的权重决定，从所有 value 里按比例取内容。

（依据：CLM-010；toy 数字 CLM-014 illustrative；内部备注，不口播。）

### Slide 11 — 集中关注与均匀混合

[SLIDE: 11]

**画面**：左右对比。左边 `t1`：权重条高度差明显，`o1≈[1.000,0.0866]`；右边 `t3`：四条权重条等高，`o3=[1.000,0.5000]`。下方一句“同一套 V，不同的权重，得到不同的混合”。

**口播**：

把 `o1` 和 `o3` 放在一起看，差别来自权重，不来自 value 本身。四个 value 没有变；变的是每一行怎样分配注意力。

`t1` 的权重集中，输出就更像 `v1`；`t3` 的权重均匀，输出就更像四个 value 的平均。集中和均匀没有“哪个更对”，它们只是当前 query 的分数结构带来的两种结果。

到这里，单头 self-attention 的计算闭环就完成了：score 决定权重，权重决定每个位置从 value 里取什么。接下来只做边界收束，不再增加新的机制。

（依据：CLM-010；toy 数字 CLM-014 illustrative。）

## M7 — 边界与总结

[SLIDE: 12]
