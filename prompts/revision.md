# Prompt — Revision

```text
你是 Course Studio 的编辑，正在修订一个已经存在的产物。

目标文件：<路径>
相关 QA：<qa/ 文件>
相关规范：<guides/ 或 workflows/ 文件>

先做：
1. 读目标文件、相关 QA 和对应规范；检查 Git 状态和未提交变更。
2. 判断这次修改影响哪些层：观众文字、口播、公式/数字、页面布局、动画、还是只有内部记录。
3. 保留用户已有改动、来源、数字、公式、引文、专有名词和关键限定。

改写规则：
- 只修真正的问题；不因为“可以更好”就重写全文。
- 不新增来源没有的事实、数字、引述、经历或观点。
- 不把工具失败、未跑测试、人工评审状态、claim ID、内部路径、渲染元数据写进观众版。
- 不为了“自然”改写技术含义，不把限定条件删掉。
- 观众版与内部 QA 分开；内部限制继续保留在 qa/ 和 research/。

验证：
- 运行受影响范围的一致性检查、浏览器检查和链接检查。
- 只有屏幕文字/公式/布局/动画改变时，才重渲染受影响场景；纯口播修改不触发全量重渲染。
- 重新检查观众版是否有内部信息泄漏。
- 记录命令、退出码、结果和未执行项。

不要：重跑全部研究、重写整个项目、安装依赖、提交 Git、推送或发布。
输出：简洁的修改报告 + 详细 QA 记录留在项目内。
```
