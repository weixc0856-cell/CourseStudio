# Delivery Quality

这份指南定义“可以交付”的最低条件。程序检查、内容正确性、视觉质量和教学效果是不同层次；不要用一个层次的通过替代另一个。

## 五个质量维度

| 维度 | 要回答的问题 | 证据 |
| --- | --- | --- |
| 内容 | 是否回答了核心问题，范围是否清楚，观众是否跟得上 | 目标、大纲、分镜、口播稿 |
| 科学准确性 | 公式、数字、单位、方向、术语、引用、限定条件是否正确 | 来源登记、主张账本、数值核验 |
| 视觉 | 版式、可读性、对齐、遮挡、动画是否解释机制 | 截图、抽帧、浏览器检查 |
| 可复现性 | 别人能否用记录的版本、命令和路径重现 | 版本、命令、退出码、锁文件、产物路径 |
| 人工审查 | 是否有人真正读过、看过、听过 | 评审记录；没有就写 `NOT_RUN` |

## 状态口径

- `PASS_VERIFIED`：实际运行并核对过，给出命令、退出码或产物。
- `PASS_STATIC`：静态检查通过，没有运行验证。
- `PARTIAL`：部分条件无法验证，写清缺哪一部分。
- `NOT_RUN`：未执行，不写成通过。
- `FAIL`：实际失败，记录错误和修复情况。

状态是证据标签，不是装饰。没有证据就不要标 `PASS_VERIFIED`。

## 阶段门

### 研究前

- 明确受众、目标、核心问题和范围。
- 确认可用的来源、工具和访问限制。
- 记录研究截止时间（新闻、市场、产品能力尤其重要）。

### 写脚本/分镜前

- 来源登记和主张账本达到可写程度。
- 关键数字、公式和术语有唯一事实基线。
- 区分事实、来源引述、分析、预测、假设和意见。

### 预览渲染前

- 分镜和口播已经对齐。
- 页面文字、旁白和动画计划使用同一组数字/符号。
- 观众版与内部 QA 已经分层。

### 正式录制/构建前

- Motion 段落已在真实浏览器 `record.html?segment=<name>` 全屏验证；不依赖 `?present`。
- Manim 兜底才做低质量预览；内容/视觉审查后再正式渲染，只重渲染受影响场景。
- Reveal 的 `data-slide` 1..N、本地 `src`/`href` 与 `.vendor` 已就绪；Slidev build 通过。
- 内容/视觉审查中发现的缺陷已修复。

### 交付前

- 数值核验、跨产物一致性、浏览器检查和链接检查实际运行。
- 观众版泄漏扫描通过。
- 内部 QA 记录完整，失败的项没有被改成通过。
- 没有自动提交、推送或发布。

## 视觉基线（2026-10 起）

默认采用麦肯锡橙白风格，适合 1920×1080 录屏；不再使用大面积纯黑背景。

| 角色 | 值 |
| --- | --- |
| 背景 | `#FAFAF7`（暖白） |
| 正文 / 标题 | `#1A1A1A`（近黑） |
| 次级文字 | `#5A5A5A` |
| 主强调 | `#E87722`（McKinsey 橙） |
| 次级强调 / 关键数值 | `#B45309`（深琥珀） |
| 边框 / 辅助线 | `#D9D9D2` / `#E5E5DE` |

- Reveal：使用 `theme/white.css` + 本集 `assets/deck.css`；不要远程字体/脚本。
- Motion：使用 `src/theme.ts` 的橙白 token；矩阵单元用白底/深灰边框/深色文字，橙色用于关键行或关键值。
- 橙色用于标题点缀、关键数值、高亮标记；不要用低对比浅灰写正文。
- 少装饰、高可读；不做花哨渐变、粒子或复杂运镜。

## 构建与录制策略

- Motion（默认）：不默认渲染 MP4；用 `record.html?segment=<name>` 在浏览器全屏播放，由 OBS 独立录制；`?probe=1` 只用于 QA 时长探针。
- Reveal（course 默认）：无构建步骤；`reveal-run.ps1` 同步 `.vendor` 后用 `python -m http.server` 服务；检查 `data-slide` 与本地资源。
- Slidev（technical/news/旧课）：P1 骨架 → P2 填充；终检实际 build。
- Manim（兜底）：迭代用低质量预览；内容/版式/数字/动画审查通过后再正式渲染；只重渲染受影响场景。
- 只改口播、不动画面文字/动画时，不重新录制/渲染视频。
- 记录命令、退出码、分辨率、时长、帧率、文件大小和路径；Motion 记录 `durationFrames/fps` 或实拍 `ffprobe`。

## 检查清单

### 数值与公式

- [ ] 张量形状、维度、方向（行/列、query/key）明确。
- [ ] 公式与代码、页面、旁白一致。
- [ ] 关键中间值有可复算的核验。
- [ ] 舍入规则一致；展示精度不超过实际精度。
- [ ] 示例数据与真实模型输出明确区分。

### 内容

- [ ] 每个重要主张有来源或明确的“分析/假设/意见”标签。
- [ ] 没有为了叙事完整而填补证据空白。
- [ ] 重要反证、替代解释或适用范围没有被隐藏。
- [ ] 新闻类内容区分已确认、引述、分析、预测和意见。
- [ ] 没有把标题、摘要或搜索片段当作已证实结论。

### HTML/浏览器

- [ ] 固定 16:9 舞台，在 1920×1080 和较小视口都能读。
- [ ] Reveal：`data-slide` 严格 1..N；本地 `src`/`href` 与 `.vendor` 存在；controls/progress/slideNumber 关闭。
- [ ] Motion：`record.html?segment=<name>` 全屏可播；`auto="true"`；无播放器 UI；`?present` 不用于录制。
- [ ] 动画页只放占位，不嵌 Motion MP4；Manim 兜底 MP4 仅用于 legacy/Slidev。
- [ ] 键盘、按钮、深链接可用。
- [ ] 没有文本溢出、裁切、控件遮挡。
- [ ] 视频路径是课程本地相对路径，能实际播放。
- [ ] 控制台无错误，无外部 CDN/运行时依赖（除非明确记录并提供回退）。

### 观众版

- [ ] 没有工具失败、未跑测试、人工评审状态、内部路径、claim ID、渲染元数据。
- [ ] 必要的教学限定仍在。
- [ ] 最后一页不是审计清单。
- [ ] 自动泄漏扫描通过。

### 可复现性

- [ ] `pyproject.toml` / `uv.lock`（Python）与 `04_motion_src/pnpm-lock.yaml`（Motion）保留。
- [ ] `segments.json`、`05_recording/manifest.json` 与 cue 一致。
- [ ] 版本、命令、退出码、产物路径记录在 QA。
- [ ] 截图/抽帧/浏览器报告保存。
- [ ] 未执行的检查明确标记。

## 人工审查

以下事项不能由程序检查替代：

- 领域专家对事实、术语、公式和限定的审查。
- 真人朗读，检查节奏、停顿、拗口和时长。
- 逐页视觉审查，检查层级、留白、颜色和动画是否真的解释机制。
- 学习者理解测试或教学效果评估。

没有做就写 `NOT_RUN` 或 `PARTIAL`。不要写成“已验证教学有效”。

## 程序检查不能证明什么

- 浏览器没有报错，不证明内容正确。
- 数值脚本通过，不证明讲解清楚。
- 页面没有溢出，不证明视觉设计好。
- 口播稿自然，不证明来源支持结论。
- AI 检测分数低，不证明文本质量高，也不证明事实正确。

## 交付包最低内容

- 观众版：Reveal/Slidev 课件、Motion 录屏、字幕/口播稿（按项目形态）。
- 录制就绪包：`05_recording/manifest.json`、cues、checklist。
- 来源登记与主张账本。
- 设计与分镜。
- 数值/一致性核验脚本及结果。
- 技术、内容、视觉 QA。
- 已知限制与未解决问题。
- 版本、命令、退出码、产物路径。
