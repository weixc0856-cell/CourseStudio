# Audience vs Internal

观众版内容、教学限定和内部 QA 是三件不同的东西。混在一起，课程会像审计报告；全部删掉，又会误导观众。这份指南定义边界。

## 三层内容

| 层 | 放在哪里 | 内容 | 示例 |
| --- | --- | --- | --- |
| 观众版 | HTML 课件、字幕、口播正文、发布说明 | 理解课程所需的信息、自然的讲解、必要的教学限定、可读的来源 | “这里的数字是为了方便手算而选的。” |
| 教学限定 | 观众版，紧挨着相关解释 | 会影响理解、适用范围或可信度的简化、近似、未覆盖范围 | “多头只画了示意图，数值部分只算了一个头。” |
| 内部 QA | `qa/`、`research/`、`scripts/` 的生产记录 | 工具失败、未执行测试、来源访问问题、审计状态、文件路径、渲染元数据、claim ID | “PyTorch 文档抓取失败，未作为证据。” |

## 观众版可以出现什么

- 理解机制所必需的定义、公式、数值、形状和方向。
- 必要的来源信息：作者、标题、arXiv 编号、章节，或可点击的原始链接。
- 会影响结论的限定：玩具示例、近似、单一 head、未覆盖的训练/评估范围。
- 自然的过渡、例子、反问和收束。
- 与画面配合的解释，而不是画面文字的逐字复述。

## 观众版不应出现什么

- 工具或文档的访问失败：“抓取失败”“未取得字幕”“接口不可用”。
- 未执行的测试、人工评审或学习效果状态：`NOT_RUN`、`PARTIAL`、`FAIL`、`PASS_VERIFIED`。
- 内部路径和文件名：`qa/`、`research/`、`scripts/`、`attention-values.json`、`source-register.md`。
- 内部编号：`S01`、`C03` 这类来源/主张编号。观众需要的是作者和章节，不是内部账本编号。
- 制作元数据：`1080p60`、`720p30`、渲染目录、场景类名、TTS、合并长视频、浏览器配置目录。
- 审计口吻：“本页不构成……”“这些是纠错，不是新的实证主张”“完整登记见 QA”。
- 对内部流程的自我说明：为什么没做、哪个工具没装、哪一步没跑。

## 必须保留的观众版限定

不是所有“限制”都要删。以下内容会改变观众对结论的理解，必须保留，并尽量放在相关解释旁边：

- 数字是手算示例，不是训练模型的输出。
- 示例只有三个 token、二维投影；真实模型的规模和表示不同。
- 多头是示意图，数值部分只算了一个头。
- 位置编码只展示了一种方案，不是唯一选择。
- 训练、反向传播、分词器实现和长上下文变体不在本单元。
- 来源之间的分歧、证据强弱、预测所依赖的条件（新闻解读尤其重要）。

写法要短、具体、贴着内容，不要集中成一页“免责声明”：

- “这个例子只有三个 token，目的是让你能自己复算。”
- “多头这里只画结构，数值只算了一个头。”
- “位置编码用正弦方案；它不是唯一选择。”

## 最后一页的规则

最后一页可以是“继续读什么”或“这套解释没有涵盖什么”，但只放观众需要的东西：

- 2–4 条真正相关的原始来源，带作者、标题、编号或链接。
- 2–4 条会影响理解的适用范围。
- 一句自然的继续阅读建议。

不要放：

- 工具失败、未跑测试、人工评审状态。
- 内部路径、claim ID、QA 文件名。
- 渲染分辨率、TTS、剪辑流程、发布状态。

## 泄漏扫描

项目内至少保留两类检查：

1. **自动扫描**：`scripts/check_consistency.py` 对观众 HTML 和口播正文禁用内部模式。
2. **人工通读**：逐页读 HTML，读口播正文，问“这句话对观众理解结论有帮助吗？”

建议的禁用模式（可按项目调整）：

```text
\bS0\d\b                 来源编号
\bC\d{2}\b               主张编号
qa/ research/ scripts/   内部路径
1080p 720p               渲染元数据
正式渲染 预览 TTS        制作流程
抓取失败 未取得 未做人工  工具/评审失败
NOT_RUN PARTIAL FAIL     QA 状态
主张账本 来源登记 审计    审计口吻
```

注意：视频 `src` 路径可能包含渲染目录；扫描时先剔除 `src="..."`，不要把必需的本地路径误判为泄漏。

## 发布门禁

观众版交付前，逐项确认：

- [ ] 每一页只包含观众理解所需的信息。
- [ ] 必要的教学限定仍在，且贴着相关解释。
- [ ] 没有工具失败、未跑测试、人工评审状态。
- [ ] 没有内部路径、claim ID、来源编号、渲染元数据。
- [ ] 来源用作者/标题/编号表达，而不是 S01/C03。
- [ ] 口播正文没有审计口吻，也没有逐字念页面。
- [ ] 最后一页是继续阅读或观众相关范围，不是 QA 清单。
- [ ] 自动泄漏扫描通过。
- [ ] 内部记录仍完整保留在 `qa/` 和 `research/`。

## 内部记录放哪里

| 记录 | 位置 |
| --- | --- |
| 来源访问日志、失败与限制 | `research/source-register.md` |
| 主张、证据强度、反证、更新条件 | `research/claims-ledger.md` |
| 数值核验 | `qa/attention-values.json`、核验脚本 |
| 跨产物一致性 | `qa/consistency-check.json` |
| 技术、内容、视觉 QA | `qa/technical-report.md`、`qa/content-review.md`、`qa/visual-review.md` |
| 已知限制、未解决问题 | `qa/known-limitations.md` |
| 本轮修订记录 | `qa/revision-report.md` |

内部记录不要求“好看”，要求可追溯、可复核、保留失败和未执行项。
