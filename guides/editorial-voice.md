# Editorial Voice

适用于中文技术课程、新闻解读、论文解读和口播稿。目标是让一个具体读者听懂，同时不改变事实；“像人写的”不是验收标准，自然也不能替代事实核验。

## 原则

1. 先明确读者此刻需要理解的问题，再决定怎么开头。
2. 用具体对象、数值、事件或现象引出概念；不要先用抽象定义堆满一页。
3. 技术准确优先。自然表达不能成为删掉限定条件、改错数字或伪造因果的理由。
4. 一段话只承担一个主要动作：解释、过渡、举例、限定或收束。
5. 允许长短句交替，允许先举例再命名，允许在读者已经理解时直接停下。
6. 旁白解释画面，不逐字复述画面。

## 反对的写作模式

- 每页机械采用“三点总结”，不管内容是否真的有三点。
- 高频使用“核心是”“本质上”“值得注意的是”“这意味着”等模板衔接。
- 反复使用“不是……而是……”制造虚假的强调；如果对比不是重点，就直接说是什么。
- 用 `PATH`、`BLOCK`、`TAKEAWAYS` 等英文标签制造专业感，却没有增加信息。
- 用整齐的三栏结构替代真正的解释；版式整齐不等于论证清楚。
- 每段都“先总结、再列点、再补一句意义”。
- 把免责声明、范围边界、工具失败、未执行测试和审计记录写进观众内容。
- 用华丽形容词、抽象大词和宏大结论代替具体事实。
- 重复解释画面中已经完整显示的公式和数字。
- 为了“口语化”故意写错、装熟、加无意义口头语，或伪造个人经历。

## 推荐的方法

- 开头先给一个具体问题或场景，例如“cat 这个词的意思从哪里来？”
- 需要公式时，先说明它在做什么，再给符号；符号第一次出现时解释。
- 按因果或数据流顺序推进，不必套用固定模板。
- 用自然的转折连接下一步：“有了权重，接下来要决定每个位置的输出。”
- 讲完一个机制后，回答“它具体做了什么”“为什么需要它”，而不是换一种说法重复结论。
- 朗读一遍。读出来显得重复、绕口或像报告的句子，删掉或改写。
- 保留作者的真实判断；不要为了“人味”编造经历、情绪或观点。

## 中文口播的具体规则

- 不要把英文 AI 词汇表直接套到中文；英文的“高频词”与中文的模板腔不是同一套东西。
- 技术术语第一次出现时解释，后续不要反复定义；同一段里不要中英文名称来回切换。
- 句子以可朗读为单位，避免一逗到底的长句；公式和矩阵前后留停顿。
- 中文标点按中文习惯使用。破折号、分号和引号要有实际作用，不要当装饰。
- 数字、单位、矩阵维度、方向（行/列、query/key）必须与核验结果一致。
- 口播稿和幻灯片分开写：页面可以短，口播要解释；不要把项目符号逐条念出来。
- 不声称“已经看过”无法访问的视频、字幕或文档；这类限制留在 QA 记录里。

## 事实保真规则（经审查后采用）

以下规则参考了公开的 `blader/humanizer` 与 `shir-danishyar/humanize` 的保留原则，经本项目审查后改写；没有复制全文，也没有安装这些 Skill。2026-10-25 通过 Skill 工具实际调用了 `humanizer` v3.1.0 的 embedded mode 审查 S08，记录见 [humanizer-invocation.md](../courses/transformer-course-pilot/qa/humanizer-invocation.md)。

- **不要改动**数字、公式、日期、单位、引文、引用、专有名词、链接目标和定义。
- **不要新增**来源中没有的事实、数字、引文、人名或引用。
- **只改表达，不改主张**。如果删掉某个句式会改变含义，就保留含义，换一种说法。
- **最小干预**：只修真正出现的问题；不要因为“可以更好”就重写整段。
- **误报保护**：技术文本中的重复、并列、被动、长句、必要的限定语不一定是 AI 腔；不要为了“多样”而拆散它们。
- **不要声称**文本通过了 AI 检测、无法被识别为 AI，或“已认证为人类写作”。评价标准是事实保真、表达自然、信息密度和受众理解。
- 代码、路径、命令、YAML、数据和链接目标不属于散文改写范围。

## 修订流程

1. 读目标文件，标记读者真正会卡住的地方：指代不清、因果跳跃、重复、审计话术、画面复述。
2. 检查数字、公式、引用、专有名词和限定条件，列出不可动项。
3. 做最小改写：先修结构，再修句子；不要逐词替换。
4. 对照原稿检查：有没有丢事实、改数字、加强结论、删掉必要限定。
5. 朗读；检查停顿、重复和语气。
6. 运行项目的一致性检查；如果是观众页，额外运行内部信息泄漏扫描。
7. 记录改了什么、为什么改、哪些没有动。

## 小例子

原稿：

> 最后用三句话收束。第一，输入路径是 token、embedding、位置和 Q/K/V。第二，注意力的核心是 softmax。第三，多头和 block 把操作堆叠起来。

改写：

> 现在再看开头那句话：cat 该从哪里读取信息？它先被切成 token，查表得到向量，再加上位置信息；然后用自己的 Query 去问所有位置的 Key，得到一组权重，再用这组权重混合各位置的 Value。

改了什么：去掉了“第一/第二/第三”的播报结构，把抽象名词换回具体动作；没有增加新事实。

## 检查清单

- [ ] 第一段是否从读者的问题或具体对象开始？
- [ ] 是否有一段只承担一个主要动作？
- [ ] 是否出现了“核心是/本质上/值得注意的是”等模板句？
- [ ] 是否有机械的三点、三栏或“首先其次最后”？
- [ ] 是否逐字复述了屏幕上已经显示的内容？
- [ ] 数字、公式、引用、专有名词和限定条件是否保持不变？
- [ ] 是否新增了来源没有的事实或经历？
- [ ] 朗读时是否顺口、停顿是否合理？
- [ ] 观众版是否混入了内部 QA 或制作状态？

## 不用这套规范做什么

这套规范不负责替作者决定观点，不负责把错误内容“写得自然”，也不负责通过任何 AI 检测器。它只约束表达方式，不替代事实核验、领域审查和人工朗读判断。
